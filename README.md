# 临床智能体变更守门

面向医联体的智能体（智能阅片、病历生成、问诊提示）变更守门服务。核心目标：
**同一模型在基层全科稳定，不代表它能直接进入儿科急诊**；供应商更新、提示词
调整、知识库变化后，已验证指标不能被默认沿用。

系统采用**事件溯源**：登记、证据、审批、暴露、漂移、阻断、回滚、召回全部是
仅追加事件。委员会可从一次版本发布完整还原证据链；科室可查询当前许可与人工
兜底要求；回滚后“曾影响哪些病例”永久保留。

## 设计原则与强制规则

| 需求 | 落地方式 |
| --- | --- |
| 登记用途边界、科室/人群、版本、队列、亚组、阈值、复核职责、窗口、灰度、覆盖理由、不良事件、召回 | `PURPOSE_REGISTERED` 与发布/验证/审批/暴露等 19 类事件，负载必填项见 `src/events.py` |
| 自动建议不能替代医生签字 | 暴露记账必须有 `signoff_physician_id`，且该开关不可由调用方关闭 |
| 高风险用途独立批准 + 最小样本 | 登记即强制样本下限（总样本 500、亚组 100）；批准要求独立批准人且不得是验证提交人 |
| 跨科室/人群不可互相背书 | 闸门按 `(release, use, scope)` 独立裁决；全科通过不影响儿科结论 |
| 泄漏/设备协议变化/亚组退化只阻断相关用途 | 闸门失败只标记当前用途；`USE_BLOCKED` 半径限定在该用途 scope |
| 漂移区分数据延迟/工作流变化/真实下降 | 信号必须先三分类；只有 `REAL_DEGRADATION` 可触发阻断、兜底或凭信号回滚 |
| 回滚后保留受影响病例 | 回滚要求病例清单覆盖全部实际暴露，缺失即拒绝；证据与暴露不删除 |
| 一次发布还原证据、审批、暴露 | `build_release_dossier` 重放事件生成完整档案 |
| 科室知道能用在哪、何时人工兜底 | `DepartmentDirectory` 仅列在线用途，标注灰度范围与兜底条件 |
| 患者数据限定原授权目的 | 闸门比对 `dataset_purpose` 与登记目的；事件负载禁止任何 PHI 字段，只允许去标识 `case_ref` |

## 放行阶段

```
CANDIDATE → VALIDATED → APPROVED → SCHEDULED → CANARY → ACTIVE
                                              ↘ HUMAN_BACKUP（漂移后强制人工兜底，仍在线）
              在线阶段 → BLOCKED / ROLLED_BACK（按用途，不连坐）
              新版本全量 → 旧在线版本自动 SUPERSEDED（证据与暴露仍在，只是退役）
```

人工兜底不能靠"激活"静默升回全量——解除防线必须登记新版本、重新验证与
重新批准。恢复期间新版本灰度与旧版本全量可并存，科室目录按用途只呈现
当前有效版本。

验证闸门检查：授权目的一致、数据版本与候选登记一致、泄漏筛查、设备协议一致、
最小样本、总体阈值、每个关键亚组的样本与阈值。

## 代码结构

- `src/contract.py` — 事件信封与时间语义（强制带时区的 ISO 8601）
- `src/domain.py` — 风险分级、阶段、漂移分类、闸门失败原因、`Scope`
- `src/events.py` — 事件种类、各事件必填负载、PHI 黑名单校验
- `src/store.py` — 仅追加事件存储（event_id 幂等、version 单调）
- `src/policy.py` — 验证闸门策略
- `src/state.py` — 事件重放得到的读模型
- `src/gatekeeper.py` — 守门命令与全部硬性规则
- `src/projections.py` — 发布档案还原、科室目录
- `contracts/event.schema.json` — 信封 JSON Schema
- `tests/` — 45 个测试，覆盖上述每条规则（含端到端场景）

## 本地检查
